# 实战应用 Prompt 模板

> 6 类可直接套用的分析模板。把 `[...]` 替换为真实对象即可，调用方式：把模板 + 你的对象贴给本 Skill，或直接说"用课程框架分析 XXX"。
> 每个模板都标注了背后调用的课程模型（详见 models_frameworks.md / cases.md）。

## 模板 1：诊断企业数字化转型成熟度
```
请用「数字化转型四阶段 + 分层适配」框架，诊断 [企业名称/行业] 的数字化转型成熟度。
要求：
1. 用四阶段（信息化→数字化→智能化→生态化）定位其当前所处阶段，并给出证据。
2. 按年营业额分层适配（五千万以下/五千万~十亿/十亿以上），判断其转型投入是否匹配体量。
3. 用「赋能 vs 重构」框架，指出其已落地的数字化动作属于赋能还是重构。
4. 列出 3 个最关键的短板与改进优先级。
参考模型：四阶段、分层适配、赋能vs重构（models_frameworks.md §3/§6/§34）
```

## 模板 2：用四 A 架构做转型顶层设计
```
请为 [企业名称] 做数字化转型顶层设计，使用「四大架构（业务/应用/数据/技术）+ 需求倒推」方法。
要求：
1. 业务架构：按业务域划分，明确战略落地与痛点模块。
2. 数据架构：列出核心数据资产目录、需要统一的标准与模型。
3. 应用架构：给出前台-中台-后台划分，标注哪些共性能力沉淀到中台。
4. 技术架构：云平台/开发平台/数据支撑平台 + 安全运维。
5. 用「需求倒推」说明：业务需求 → 需要什么数据 → 倒推什么算法/系统。
6. 强调 CIO 与 CDO 职责分设。
参考模型：四A架构、中台、需求倒推、单点实施（models_frameworks.md §8/§9/§10/§12）
```

## 模板 3：用商业模式画布 + 价值捕获拆解一门生意
```
请用「科技增强版商业模式画布（九维度）+ 价值捕获（五种变现）」拆解 [某生意/产品/企业]。
要求：
1. 九维度逐一填写：价值主张、客户关系、渠道、客户细分、收入来源、核心资源（数据与算法）、关键业务（数据治理）、重要合作、成本结构。
2. 用一句话（≤50 字）概括其商业模式 one-liner。
3. 用价值捕获五种方式（直销/佣金/数据变现/效率重构/生态变现）分析其"怎么赚钱"。
4. 判断其处于商业模式 1.0–6.0 哪一阶段。
5. 在存量时代五大创新方向中，它契合哪一个、还缺哪一个。
参考模型：画布九维度、价值捕获、1.0-6.0、存量五大方向（models_frameworks.md §25/§26/§27/§28）
```

## 模板 4：判断某 AI 应用是「赋能」还是「重构」
```
请用「赋能 vs 重构」框架判断：[某 AI 应用/系统，如 XX 智能排产、XX 智能客服]。
要求：
1. 判定它是赋能（不改变流程与组织、人主导决策、工具提效）还是重构（重设流程、人机协同决策、数据与模型成核心结构）。
2. 给出 3 条判定依据（是否改变业务流程？是否改变组织结构？决策由人还是系统主导？）。
3. 如果是赋能，指出它是否有机会升级为重构、风险与收益是什么。
4. 引用课程案例类比（美的排产/顺丰可视化/阿里开放平台等）。
参考模型：赋能vs重构、四阶段、数字化组织三特征（models_frameworks.md §34/§3/§35）
```

## 模板 5：制定数据治理落地方案
```
请为 [企业名称] 制定数据治理落地方案，使用「数据治理九大模块 + 数据质量六维 + 数据资产化两步法」。
要求：
1. 九大模块落地清单：战略规划、组织设计、标准体系、资产管理、质量管理、主数据、元数据、生命周期、安全管理。
2. 组织保障：治理委员会 + 执行团队，CIO 与 CDO 分设，组织/制度/流程三层保障。
3. 数据质量六维（规范/完整/准确/一致/时效/可访问）的当前评估与 PDCA 改进。
4. 数据资产化路径：原始数据→治理→数据资源→市场化运营→数据资产，并提示"高价值数据多线下私售"的合规边界。
5. 先治理后 AI：说明为何无治理会训练出"邪恶大模型"。
参考模型：数据治理九模块、质量六维、资产化两步法（models_frameworks.md §13/§14/§15）
```

## 模板 6：制定数字化转型实施路线图
```
请为 [企业名称] 制定数字化转型实施路线图，使用「一个目标·两个支撑·四个行动 + 单点实施」。
要求：
1. 一个目标：明确为什么转、转什么、解决什么真实痛点（非"上面下文件"）。
2. 两个支撑：组织机制支撑、数据文化支撑（一把手工程、用数据说话）。
3. 四个行动：设计体系架构 → 数据治理 → 搭建平台 → 持续迭代。
4. 实施节奏（参考课程周期）：规划 1–2 月、数据治理 5–6 月、系统上线 2–3 月、一年基础建设、再 6–8 月上 AI、两年完成。
5. 单点切入：选 1 个核心痛点模块先验证价值，避免全量风险。
6. 输出里程碑甘特图（文字版）。
参考模型：实施方法论、单点实施、四A架构（models_frameworks.md §11/§12/§8）
```

## 通用分析原则（每次实战应用都默认遵守）
1. 业务驱动、需求倒推：先业务后系统，不做"为开发而开发"。
2. 治理先行：任何 AI 应用绕不开数据治理。
3. 阶段不可跳级：没数据不能从小学跨到大学。
4. 一把手工程：跨部门利益冲突需一把手协调。
5. 价值创造导向：凡不打兔子（不创造增量价值）的都不叫转型。
6. 数据主权：核心数据必须掌握在企业自己手里。
