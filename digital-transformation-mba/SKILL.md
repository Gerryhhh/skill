# 数字化转型与商业分析 · MBA 课程 Skill

一套源自 MBA 课程录音（7 份讲稿、5 大主题）的结构化知识库与实战应用框架。既能**问答/速查**课程概念与模型，也能把课程里的数字化转型方法论与商业分析框架**应用到真实企业/作业**中。

## 何时使用

- 解释数字化转型概念：赋能 vs 重构、信息化/数字化/智能化、九字诀、四阶段。
- 解答框架问题：四 A 架构、数据治理九模块、数据质量六维、商业模式画布、价值捕获、技术战略四象限。
- 诊断企业数字化成熟度（四阶段 + 分层适配），设计转型路线图（一目标·两支撑·四行动）。
- 用商业模式画布 / 价值捕获 / 1.0–6.0 拆解或设计一门生意。
- 判断某个 AI 应用是「赋能」还是「重构」。
- 制定数据治理落地方案、数据资产化路径。
- 引用课程案例（美的、青岛啤酒、瑞幸、华为、中石油、贝壳、陕鼓、希音、森马、鞍钢、百果园、建发、卡奥斯、万华、海尔卡沃斯等）支撑观点。
- 分析 **AI 对不同规模企业（大/中/小微）的落地路径与组织影响**：分规模策略、一把手工程、四大权力重构、智能体工厂。
- 拆解 **产业互联网**：钻石模型、八类商业模式、三阶段、与消费互联网差异、希音/百果园/建发/找钢等案例。
- 讲清 **工业互联网**：四层架构、标识解析、四类应用模式、机理模型 vs 数据模型、树根/卡奥斯/徐工汉云案例。
- 选型 **工业智能体**：六大工业智能体、AI 与工业互联网融合四阶段、海尔卡沃斯/万华化学案例。

## 核心模型速查表（详见 references/models_frameworks.md）

| 模型 | 一句话定义 | 关键判定 |
|---|---|---|
| 九字诀（数字化—网络化—智能化） | 采集数据→让数据流动→算法赋能业务 | 只采集不流动不赋能=信息化，不算转型 |
| 打兔子模型 | 信息化=上系统；数字化=用数据提效；智能化=算法替代人 | 不创造增量价值的不叫转型 |
| 四阶段（信息化→数字化→智能化→生态化） | 阶段可叠加不可跳跃 | 没数据不能从小学跨到大学 |
| 四 A 架构（业务/应用/数据/技术） | 转型顶层设计"四张图纸" | 不做即方法论错误；CIO≠CDO |
| 需求倒推 | 业务需求→数据→算法→系统 | 先建系统再找需求是本末倒置 |
| 数据治理九模块 + 六维质量 | 全球通用治理体系 | 无治理=黑暗数据→邪恶大模型 |
| 数据资产化两步法 | 治理→资源，市场化运营→资产 | 高价值数据多线下私售，不公开标高价 |
| 商业模式画布（九维度） | 用技术变量拆解一门生意 | one-liner 超 50 字即失败 |
| 价值捕获（五种变现） | 技术价值如何变收益 | 不赚钱的模式不可持续 |
| 赋能 vs 重构 | 赋能提效不改结构；重构重设流程 | 智能化是重构不是赋能 |
| 数字化组织三特征 | 赋能·共生·协同 | 只有内部系统无外部协同=未闭环 |
| 分层适配 | 五千万/十亿分界 | 小企业别烧钱，大企业必全转 |
| 企业规模分层定位 | 大=重构 / 中=聚焦核心不自研大模型 / 小=轻量赋能 | 同一规模内行业差异大，需结合自身校准 |
| 企业 AI 转型铁三角 | 找对场景 + 沉淀独特业务数据 + 组织执行力 | 三者缺一不可，否则沦为概念 |
| 四大权力重构 | 信息权/决策权/协调权/闭环权被 AI 改写 | 中高层/白领受冲击最大，3-5 年完成调整 |
| 产业互联网钻石模型 | 上游发起组织+中游（资本/技术/商业）+下游生态 | 必答资本/盈利/技术三问，须头部背书聚生态 |
| 工业互联网四层架构 | 边缘层/IaaS/PaaS(微服务)/应用层(工业APP) | 中小企业免开发、接入即用 |
| 机理模型 vs 数据模型 | 讲因果（可解释）vs 讲关联（需约束） | 机理更重要，先定因素再机器学习 |
| 数据+模型=服务 | 设备/ERP 数据经 PaaS 模型封装为 APP | 工业互联网平台核心公式 |
| 工业智能体 | 感知为眼耳+大模型为脑+自主决策迭代 | 非单台设备，模型不可跨企业通用 |
| 六大工业智能体 | 生产管控/质量检测/设备预维护/能耗安全/供应链/研发 | 国家重点，直击车间痛点 |
| AI+工业互联网融合四阶段 | 单点应用→流程集成→价值链贯通→产业生态 | 不可盲跳阶段，底层皆数据 |

## 应用工作流

### A. 知识库问答
1. 先用 Grep 在 `references/` 与 `sources/book_content.md` 中检索关键词（模型名/企业名/概念）。
2. 命中后按"定义→适用场景→作用/影响→慎用情形"四段式回答，保留课程原术语。
3. 涉及案例时引用 `references/cases.md` 中的背景/做法/结论。

### B. 实战应用（用课程框架分析真实对象）
按 `references/application_prompts.md` 中的模板执行，典型流程：
1. **诊断**：用四阶段 + 分层适配定位企业当前成熟度。
2. **设计**：用四 A 架构做顶层设计，需求倒推拆系统。
3. **治理**：先数据治理九模块 + 六维质量，再做 AI/智能化。
4. **判断**：用赋能 vs 重构框架界定每个 AI 应用的变革层级。
5. **落地**：用一目标·两支撑·四行动制定路线图，单点切入快速验证。

> 黄金原则：**凡不打兔子（不创造增量价值）的都不叫转型；数字化转型是一把手工程；治理先行，业务驱动，需求倒推。**

## 关键原则（来自课程反复强调）

1. **不创造价值的都不叫数字化转型。**
2. **数字化转型是一把手工程**，跨部门利益冲突需一把手协调。
3. **治理先行**：任何 AI 应用都绕不开数据治理，黑暗数据训练出邪恶大模型。
4. **业务驱动、需求倒推**：先有业务架构，再有应用/数据/技术架构。
5. **阶段不可跳级**：信息化→数字化→智能化→生态化，没数据不能跨级。
6. **智能化是重构不是赋能**：系统自主运行、人机协同决策才是真转型。
7. **数据是企业核心资产，必须自主掌控**（云技术主权）。
8. **人不会被 AI 淘汰，但不会用 AI 的人一定会被淘汰。**
9. **先数字化、再智能化**：跳过数字化直接上 AI 会"垃圾进垃圾出（GIGO）"；先用 6-18 个月采集高质量数据、小范围试点验证再推广。
10. **凡不创造价值的转型都跟我们无关**：企业内与产业链上的降本增效，都必须产生真金白银的价值。
