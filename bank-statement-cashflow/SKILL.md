# 银行流水 → 月度现金流量表

把银行流水按自定义类别逐月汇总，产出带校验的 Excel。核心不是"算出来"，是"算得能被证明没错"。

## 流程

### 1. 解析 PDF

```bash
pdftotext -layout input.pdf out.txt     # -layout 保留列对齐，务必加
```

用正则按列取数（列序以实际表头为准，先 `head -60 out.txt` 确认）：

```python
pat = re.compile(r'^(\d{4}-\d{2}-\d{2})\s+(\d{2}:\d{2}:\d{2})\s+(\S+)\s+'
                 r'(-?[\d,]+\.\d{2})\s+(\+?-?[\d,]+\.\d{2})\s+([\d,]+\.\d{2})\s+(.*)$')
rows = [m.groups() for l in open('out.txt',encoding='utf-8').read().split('\n') if (m:=pat.match(l))]
```

**必做**：`len(rows)` 要等于「以日期开头的行数」，确保没漏抓。

### 2. 探查类别（不要先猜，先看全量）

```python
Counter(r[6].split()[0] for r in rows)
```

再按类别打印笔数 / 支出合计 / 收入合计，并把每类的对手方账号打出来——**对手方账号相同只是摘要不同 = 同一供应商更名/改记账口径，必须合并**（如「水费」与「用水费」）。

### 3. 先跟用户确认口径再生成

必须问清的三件事（一次只问一个）：
1. 只统计支出，还是收支都要体现
2. 边缘类别的归属（如「有线电视费」算通讯费还是单列）
3. 取现/转账这类"非费用"支出怎么放（建议单列，不要塞进「其他」）

用户若说"全部都要归类、不要其他"，就给每个原始摘要单独一行，绝不合并成「其他」。

### 4. 余额连续性校验（最强的正确性保证）

```python
for i in range(1,len(rows)):
    p,c = rows[i-1],rows[i]
    if abs((f(p[5]) + f(c[3]) + f(c[4])) - f(c[5])) > 0.005: errs += 1
```

支出列存的是负数，所以 `上笔余额 + 支出 + 收入 = 本笔余额`。零误差才说明抓全、抓对。

### 5. 生成 Excel

工作表结构：
- `年度总表`：现金流量表格式（一、收入 / 二、支出 / 三、收支净额 / 四、账户余额含期初期末与校验行）+ 月度明细矩阵（行=月份，列=各类别）+ 数据校验说明区
- 每个月份一张表（同名 `YYYY-MM`），同一套现金流量表格式
- `流水明细`：全量原始交易 + 「归类」标签列，开 auto_filter 供抽查

月期初余额 = `首笔余额 - 首笔支出 - 首笔收入`（支出为负数）；月期末余额 = 末笔余额。

格式约定：数字 `#,##0.00`，占比 `0.0%`，表头浅蓝底 `DCE6F2`、合计浅黄底 `FFF4D6`、净额橙底 `FDEBD0`，字体微软雅黑，边框细线。写**静态值**不用公式，保证任何预览器都能显示。

### 6. 复核（独立路径，不是重跑同一段代码）

生成后重新 `load_workbook(..., data_only=True)`，反向验算：
1. 每月：明细相加 = 合计；收入−支出 = 净额；期末−期初 = 净额
2. 12 个月累加 = 年度总表，且逐类核对
3. 矩阵合计行横向 = 各类之和；纵向 12 行 = 合计行；每行 = 对应月度表
4. 从「流水明细」重新分类汇总，结果必须 = 年度总表

## 多来源合并（如 微信账单 + 银行卡流水）

微信导出账单 xlsx 的结构：前 18 行是说明区（表头在第 18 行），数据从第 19 行开始。关键列：
`交易时间 / 交易类型 / 交易对方 / 商品 / 收-支 / 金额(元) / 支付方式 / 当前状态 / 交易单号 / 商户单号 / 备注`。
`收/支` 列取值 `收入` / `支出` / `/`（`/` 即微信定义的「中性交易」：提现、零钱通存取等）。

**合并时的头号陷阱是重复计算**：微信提现额与银行卡收到的汇入款是同一笔钱，两边都计收入会虚增。处理办法是分段列示：

```
一、经营收入     ← 只有真实进账（收租、红包、退款、利息）
二、经营支出     ← 按渠道分组：微信支付（商户消费/转账支出/扫码付款）+ 银行卡支付（水电电视通讯…）
三、经营净额
四、资金调拨     ← 提现/卡间转入/取现，标注「不计入收支」，仅列示
```

方向约定：提现、零钱通转出记**负**（流出），卡间转入记**正**（流入），这样调拨净额 = 停留在中间卡的余额变化。

必须问清的口径（一次一个）：①合并范围 ②「净收入」定义——转给自己/取现算支出还是调拨 ③个人消费是否从经营支出中剔除。
微信账单常混有私人消费（医院、超市、停车、ETC），若用户只要经营口径，需另加一列人工打标。

## HTML 可视化看板

单文件、无 CDN 依赖（用户可能离线打开）；用原生 JS 手写 SVG 渲染，别引 Chart.js。常用图型：
分组柱+折线（收入/支出/净额）、环形图（结构占比）、柱+累计折线（双轴）、多折线（水电走势）、堆叠柱（渠道分担）。
**折线与柱共图时务必共用同一纵轴刻度**，否则读者会误读。

验证方式：抽出 `<script>` 用 `node --check` 查语法；再用一个 DOM 桩（`document.createElement(NS)`/`getElementById` 返回假节点）跑一遍，确认无运行时错误且各月切换都能渲染；最后用
`"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --screenshot --window-size=1280,5400` 截图肉眼查版式。

## 踩过的坑

- **列号偏移**：`cols.index('支出合计')` 是 0-based，转 openpyxl 列号要 `+1`。复核脚本报 ERR 时先怀疑脚本而不是文件。
- **全角空格**：单元格标签用 `'　　'` 缩进，比对时先 `.strip()`（Python strip 会去掉 U+3000）。
- **分组标题行**：`一、收入` / `四、账户余额` 这类行没有金额，复核脚本要显式跳过，否则取到 None。
- **摘要被 PDF 截断**：如「手机银行卡号转账（行」少了「内)」。不要脑补补全，用截断前的部分命名。
- **托管 venv 会被沙箱拦截**：改用 `python3 -m pip install --target /tmp/pylibs openpyxl` + `sys.path.insert(0,'/tmp/pylibs')`。
