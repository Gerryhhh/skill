# 决策速查表

## 先问什么

| 如果看到 | 先追问 |
|---|---|
| “有很多用户/流量” | 谁付钱？付多少？何时付？获客和服务成本是多少？ |
| “市场有千亿规模” | 哪个细分市场？公司在价值链中拿哪一段？真实收入/费率是多少？ |
| “技术领先/AI 很热” | 客户的刚性痛点是什么？现有替代方案为何不够？是否已持续付费？ |
| “收入快速增长” | 毛利、回款、应收账款、CCC 和现金跑道是否同步改善？ |
| “估值很贵” | 谁愿意以该价格买？增长、壁垒、现金和竞争是否支撑价格？ |
| “公司已上市/获得曝光” | 价值创造和可持续收入是否成立？上市不是质量证明。 |

## 项目判断顺序

1. 问题是否真实、严重、频繁、紧迫？
2. 使用者、决策者、付款者是否同一个人？
3. 方案带来的结果是否优于替代品？
4. 市场口径是否已经从 TAM 缩到可获得收入？
5. 获客、交付、复购和变现是否可复制？
6. 竞争、替代品、渠道和政策会不会压缩利润？
7. 收入能否变成现金？
8. 最后才比较估值、稀释、控制权和预期回报。

## 早期项目与成熟项目的侧重点

| 阶段 | 优先看 | 慎用 |
|---|---|---|
| 早期、无稳定收入 | 问题、方案、团队、市场、商业模式、验证速度 | 过度精确的财务预测、机械 PE |
| 已有收入、扩张期 | 单位经济、GTM、复购、毛利、现金转换、竞争壁垒 | 只用用户量或 TAM 讲增长 |
| 成熟/上市前后 | 收入质量、利润、现金流、资本结构、估值与回报 | 把市场热度当内在价值 |

## 路演底线

不要照搬招股书的“公司解决什么问题”；用客户和买方语言重写。每一个数字注明来源和核验状态；每一个结论写出支撑证据与反证条件。
