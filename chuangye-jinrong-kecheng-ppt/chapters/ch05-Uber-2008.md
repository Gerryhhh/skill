# Chapter 5：Uber 2008（课件 15）

## Core Idea

分析 UberCab 必须回到 2008 年，而不是用后来成功的结果倒推 BP。课件通过手机、车辆、调度和市场背景，训练投资人从有限信息中识别客户、问题、方案、成本和时机。

## Frameworks Introduced

- **历史时点重建**：考虑 iPhone/GPS、BlackBerry、金融危机、闲置劳动力、美国汽车社会和出租车牌照壁垒。
- **BP 问题定义**：区分乘客痛点、司机痛点、调度系统问题和技术方案。
- **颠覆判断**：不是“更贵的车”就颠覆，而是是否改变叫车、调度、支付、定位、供给组织和用户行为。

## Key Concepts

早期名称是 UberCab；图示暗示高端黑色车辆、商务客群、司机端和乘客端设备。早期方案包含叫车、司机—乘客连接、调度、定位、支付和声誉追踪等假设。

## Worked Example

从一张早期 BP 图反推假设：两部手机意味着双边连接；高端设备意味着商务定位；黑色汽车意味着较高成本和服务标准；手机定位/调度意味着技术依赖。再逐项问：谁愿意付费、供应能否获得、需求是否足够频繁、现有出租车为何不能解决。

## Anti-patterns

- 用 Uber 后来的规模证明早期 BP 每一项都正确。
- 把技术方案写成客户问题。
- 只说“颠覆”，不说明改变了哪项行为或市场规则。

## Key Takeaways

1. 一页 BP 的图片和设备选择也包含客户、成本和定位信息。
2. 创业判断要把时代背景纳入市场分析。
3. 方案只有连接到客户结果和行为改变，才可能成为价值创造。
